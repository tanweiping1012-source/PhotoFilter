# 人物与风景分开筛选规格

## 用户问题

旅行照片中的人物照和风景照具有不同的取舍标准。人物照更看重表情、姿态、互动和人物与环境的关系；风景照更看重空间层次、构图、光线和氛围。把两类照片放在同一候选池中排序，会让分数和最终名额互相挤占，也无法得到清晰的分类导出结果。

## 简化交互

主界面只增加一个稳定的“照片类型”三段选择：

- 全部：总览全部照片和两类保留进度，不发起新的整轮 AI评分。
- 人物：只显示人物照片；候选、AI评分、全局排序和采纳均只在人物照片内进行。
- 风景：只显示风景照片；候选、AI评分、全局排序和采纳均只在风景照片内进行。

现有“照片筛选”继续只负责“全部照片 / 待AI评分 / 已AI评分 / 评分优先 / 保留 / 淘汰 / 待定”。照片类型和处理状态是两个正交条件，不增加新的复合菜单项。

左侧“保留目标”固定显示人物和风景两行目标及进度。默认总数仍为 12 张，拆分为人物 6 张、风景 6 张；用户可分别调整为 0–999 张。只有两类都达到各自目标时，才允许最终导出。

## 本地分类

- “人物”表示人物承担主要视觉主题，不等于画面中只要含有人。
- 扫描后的后台分析使用 Apple Vision 在本机组合完整人体、人脸质量、人物分割和注意力显著区域，不上传图片，也不读取 API Key。
- 清晰正/侧脸主体、大比例人物主体，以及与风景共同构图的显著人物或剪影归为人物；远处路人、背景人群和不显著小人归为风景。
- 详细规则和阈值见 `docs/PEOPLE_SUBJECT_CLASSIFICATION.md`。
- 分类是整理入口，不是不可更改的事实。照片卡菜单和大图详情都提供“人物 / 风景”纠正操作。
- 用户纠正值优先于后台分析，并作为相对路径配置随项目持久化；自动分类结果不持久化，重新打开项目时可重新计算。
- 修改类型后，清除该照片已有的分类评分优先状态和整轮分类评分，防止旧类别分数进入新类别排序；人工保留或淘汰决定不变。

## 分开评分

- 人物和风景分别生成本地待评分池，不共享名额，也不跨类别形成最终排序。
- 人物 Prompt 使用固定绝对标尺，重点观察表情、姿态、互动、遮挡、人物清晰度和人物与环境的关系；不得推断身份或敏感属性。
- 风景 Prompt 使用同一分数范围，重点观察空间层次、构图、光线、氛围和地点叙事；不得因为画面中没有人物而降低分数。
- 每次请求仍只发送 2–5 张同类型、匿名、无元数据 JPEG。传输窗口不代表比较组。
- 全部候选完成后，App 只在当前类型内全局排序并取该类型剩余名额的前 N 张。
- 人物和风景的运行进度、失败状态、评分优先集合彼此独立；同一时间仍只允许一个网络评分任务。
- “全部”视图可以汇总查看和一次采纳两类已完成结果，但不能把两类分数混排成一个名次。

## 分类导出

- 底部仍只保留一个导出主入口。
- 导出前分别校验人物保留数和风景保留数。
- 一次确认后创建一个时间戳目录，内部固定分为“人物”和“风景”两个子目录。
- 根目录 `selection.json` 和 `selection.csv` 记录类别与相对文件名，不包含原始绝对路径、AI 响应或 API Key。
- 导出只复制原图；任何分类、评分和清单操作都不能移动、覆盖、改名或修改源照片。

## 新手引导

内置 8 张样例改为 4 张人物、4 张风景，目标为人物 2 张、风景 2 张。任务扩展为八步：

1. 在“照片类型”中选择人物。
2. 打开任意人物照片查看大图。
3. 保留实际打开的照片。
4. 运行离线 AI评分；固定结果按人物和风景分别应用及排序。
5. 切换到风景，理解两类照片独立浏览。
6. 查看一张风景照片的分类评分详情，并点击明确的“评分已查看，继续”返回网格。
7. 点击“显示评分优先照片”，检查后采纳人物和风景结果。
8. 导出 4 张副本，确认输出包含人物和风景两个目录。

每一步继续使用红色动态框和小指针指向真实控件；完成后继续以“结束新手引导”为主按钮。

## 迁移与失败边界

- 旧项目只有总目标 N 时，首次载入按 `ceil(N / 2)` 和 `floor(N / 2)` 拆为人物、风景，保证总数不变。
- 分类尚未完成时可以浏览和人工决定，但不能开始整轮 AI评分。
- 当前类型没有足够候选时，只提示调整该类型目标或继续人工筛选，不借用另一类型照片填充。
- 某一类型评分失败时，不影响另一类型已经完成的评分和人工决定，也不能生成该失败类型的不完整最终结果。
