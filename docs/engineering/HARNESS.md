# 旅行照片筛选器开发与运行 Harness

## 目标

Harness 把每次迭代限制为“任务卡 → 纯逻辑测试 → App 视觉验收 → 真实目录只读校验”。Codex 负责执行，仓库中的规则、任务卡、数据契约和脚本负责约束执行。

## 开发循环

1. 从 `docs/engineering/TASKS.md` 选择一张任务卡，写清输入、输出、非目标和可观察验收结果。
2. 先实现无 UI、无网络的纯逻辑，并用合成数据覆盖正常、边界和冲突场景。
3. 接入 ViewModel 和 SwiftUI；任何删除操作只能删除 App 项目状态或缓存，不能作用于源目录。
4. 运行 `scripts/check.sh`。
5. 通过 `scripts/run-app.sh --verification` 启动标准 `.app`，检查窗口最小尺寸、项目切换、始终可见操作区和筛选结果。
6. 对真实只读目录运行哈希前后对比；报告照片数、候选数、相似簇最大规模、普通照片覆盖数和源目录是否改变。

## 运行时漏斗

```text
项目文件夹（只读）
  → 递归索引与异步低清分析
  → 本机人物主题判断并分为人物 / 风景
  → 视觉相似识别（时间仅辅助边界匹配）
  → 相似照片家族折叠（每个家族一个本地代表）
  → 普通照片按时间线分层抽样
  → 人物 / 风景各自的受控待评分池（每个最终名额最多 5 张；上限随剩余目标放宽，默认目标下为 48 张，绝对上限 240 张）
  → AI 每次传输 2–5 张同类型照片并逐张独立评分
  → 当前类型全部候选按统一分数做类型内全局排序
  → 最终相似冲突审计
  → 人工确认
  → 复制导出
```

> 下面三节只列"必须守住的边界"。字段级定义、容量常量和错误分类见
> [数据契约](DATA_CONTRACTS.md)，不在这里重复。

### 候选覆盖门禁

- 同一候选家族最多一个成员进入 AI；家族只由画面相似集合建立。
- 家族中已有人工 `keep` 时，其他成员不会进入 AI；若用户人工保留同一家族多张，App 必须提示冲突，不能声称已得到无重复最终结果。
- 普通照片不会因“没有相似关系”被排除；容量不足时按时间线分段抽样。
- 待评分池不是全量上传清单。任何网络发送仍需用户再次确认；确认弹窗只说明模型、张数和照片类型，请求节奏与费用规则放在“帮助与支持”。
- 容量只是上限参考，不能作为必须填满的目标。候选池规模**倾向于**每个剩余名额 2 张比较图，本地信号足够强时才扩展到 3 张；达到足够场景覆盖后应提前停止，不能用同场景或明显较弱照片凑数。
- 这只是规划器的规模偏好，**不是开始评分的前置条件**：相似照片折叠后独立候选可能少于目标，此时仍必须允许开始，最终按实际可得数量收敛。
- 严格视觉相似可跨时间识别；边界视觉相似必须同时满足时间接近。同一场景家族最多输出一个本地代表。时间接近但画面无关的照片不得折叠或形成最终冲突。

### 最终结果门禁

- JSON schema、匿名 `photo_id`、总分、五维评分、具体评价和总结全部通过本地校验。
- 类型内全局排序必须覆盖本轮固定候选池中的每张照片；取前 N 张，N 为该类型剩余目标与实际候选数中较小的一个，人物和风景不得跨类型比较。
- AI 胜者与人工锁定照片合并后再次执行候选家族冲突检查；冲突时结果不生效。
- `已AI评分` 必须包含所有有效评分照片，`评分优先` 只表示整轮胜出集合；界面必须区分人工锁定照片与本轮 AI 新增照片。

### AI 失败恢复门禁

- HTTP 成功不等于结果可用；响应外层、工具/JSON 载荷和业务字段仍须分阶段校验，但诊断信息不能包含原始响应或照片数据。
- 可自动重试：模型输出格式或可恢复的字段校验错误、HTTP 429、HTTP 5xx、连接超时与网络中断；
  每批最多 4 次，按指数退避并优先遵守服务端返回的 `Retry-After`。
- 不得重试：鉴权失败、模型权限不足、模型 ID 错误和其他不可恢复的 HTTP 错误。
- 每一次请求尝试都必须更新自适应冷却时间；发送确认必须披露自动重试可能增加请求与费用。
- 最终失败时保留当前运行上下文和已完成评分，界面必须显示“重试第 N–M 张/放弃本轮”——用户可见文案一律用照片范围，不暴露批次；失败态不能被“上下文仍存在”的运行态判断遮住。
- 人工重试只从失败批次继续；不得重复发送已经完成的批次，也不得用不完整结果生成 `评分优先` 集合。

## 项目生命周期

```text
新建项目 → 扫描/分析 → 筛选/AI → 人工确认 → 导出
    ↘ 切换项目：保存会话状态、取消旧分析会话、恢复目标项目
    ↘ 删除项目：确认 → 移除会话状态 → 清空缩略图缓存 → 返回项目列表
```

- 删除项目永远不调用源目录的删除、移动、覆盖或改名 API。
- 活动 AI 请求期间禁止切换或删除项目，本地分析期间同样禁止（半分析状态无法安全恢复）。
  两种情况都必须在被禁用的入口旁写明还要等什么，而不是只置灰。
- 一轮评分只锁它自己那一类：另一类的浏览、决定、撤销和目标调整必须照常可用。
- 跨 App 重启使用 security-scoped bookmark；持久化文档只包含 schemaVersion、书签、显示名、目标数、相对路径人工决定和最近活动项目。
- 重启后重新扫描和本地分析，不持久化缩略图、技术分析缓存、AI 预览或 AI 原始响应；扫描结果只按相对路径合并已保存的人工决定。
- 书签失效时保留侧栏项目并显示“需要重新授权”；重新授权必须由用户通过系统文件夹选择器完成。
- 每次人工决定、目标变化、项目切换和 App 退出前原子保存；删除项目同时删除对应持久记录并停止 security-scoped access。

## App Store BYOK 门禁

- AI 能力只接受用户为已接入供应商自行配置的 API Key，不接入 IAP、订阅、开发者代充或自建 AI 计费后台。
- 每个供应商 API Key 仅进入独立 Keychain 条目与该供应商单次 HTTPS 请求的 Authorization 头；不得进入 UserDefaults、项目 JSON、崩溃信息、截图或内置样例数据。
- App 内不得出现购买或充值第三方 API Key 的按钮、链接或引导；本地筛选、人工决定和安全导出在没有 Key 时仍完整可用。
- 每次发送前继续展示缩略图数量、最长边、去元数据、第三方目的地与潜在费用；未确认不发送。

## 性能门禁

- SwiftUI `body` 不允许同步读取或解码原图。
- 缩略图缓存同时设置 `countLimit` 和 `totalCostLimit`，项目删除后可显式释放。
- 撤销历史记录照片决定的差异，不复制完整照片数组。
- 本地分析继续使用低清灰度图；结果按批次合并，过期分析会话不得覆盖当前项目。
- 真实验收至少覆盖 168 张目录；发布前再覆盖 1,000–2,000 张公开样例。

## 交互唯一性门禁

- 同一页面、同一状态、同一用户目标只保留一个可见主操作入口。例如评分集合由统一筛选器负责，当前照片的“查看评分”复用同一大图预览，“复制导出”由固定底部操作区负责。
- 计数、运行状态和完成提示使用文本或状态标签，不得再提供一个执行相同命令的按钮。
- 允许键盘快捷键、右键菜单和无障碍操作作为替代输入方式，但它们必须调用同一 ViewModel 命令，不能形成独立状态分支。
- UI 改动验收必须搜索同一 ViewModel 命令的所有调用点，并检查未被 `body` 使用的旧 View 是否仍残留重复交互。
