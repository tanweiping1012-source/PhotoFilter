# 数据契约

## PhotoItem

- `id`：由本地文件 URL 生成的稳定标识。
- `url`：仅在运行时本机使用的原图地址。
- `filename`：展示和导出的文件名。
- `captureDate`：优先为 EXIF 原始拍摄时间；缺失时使用文件创建/修改时间，用于本地时间线排序，并在画面中等相似时提供辅助置信度。
- `perceptualHash`：运行时内存中的 64 位灰度缩略图指纹与亮度特征，仅用于本地近重复比较；不写入导出文件或版本库。
- `technicalQuality`：运行时内存中的低清清晰度、动态范围与极端亮度比例，只形成风险提示；不参与自动淘汰，也不写入导出文件或版本库。
- `curationCategory`：运行时人物主题/风景分类。后台通过 Apple Vision 在本机组合完整人体、人脸捕获质量、人物分割和注意力显著性；只有清晰人像、大比例人物主体或显著人物风景/剪影为 `people`，远处路人和背景人群仍为 `scenery`。用户纠正值优先于自动分析。
- `isCurationCategoryUserAssigned`：区分用户纠正与自动结果；只在用户纠正后为 `true`，防止后台分析覆盖人工选择。
- `decision`：`undecided`、`keep` 或 `reject`。
- `burstGroup`：旧版本兼容字段；新分析始终清空，不参与候选、排序、AI评分或最终冲突。
- `similarityGroup`：可选的画面相似照片标记，包含集合 ID、位置与总数；不改变 `decision`，不参与导出清单。
- `localRecommendations`：可选的相似照片本地技术排序，记录名次、总数和说明；不改变 `decision`，不参与导出清单，也不是 AI评分。
- `aestheticRecommendations`：只有通过严格契约校验后才会出现的 AI评分记录；保存评分范围、0–100 总分、瞬间/构图/主体/光线/叙事五维分、1–3 条具体评价和总结。它不改变 `decision`，不参与导出清单，也不落盘。

## AI评分（默认关闭，多供应商 BYOK）

模型结果的 JSON Schema 位于 [评分 JSON Schema](../ai/REVIEW_SCHEMA.json)。每次请求只生成临时的 `photo_001`、`photo_002` 等匿名 ID：本地路径和原始文件名不会作为模型输入的一部分。

- AI评分只通过当前人物或风景类型的完整候选池入口启动，不提供单个相似照片集合的局部评分。
- 每个评分 scope 带有 `people` 或 `scenery` 类别，且同一次请求只能包含同类照片。人物和风景分别形成候选池、运行进度与最终结果。
- 人物 Prompt 重点观察表情、姿态、互动、遮挡、人物清晰度和环境关系；风景 Prompt 重点观察空间层次、构图、光线、氛围和地点叙事。两类继续共享 0–100 固定绝对标尺。
- 视觉模型必须为每张候选返回 0–100 的整数总分、五个 0–100 维度分、1–3 条具体评价和总结。
- 即便服务端采用 JSON Schema，App 仍会校验版本、请求 ID、当前评分范围、匿名 photo_id 集合、总分与维度范围、具体评价和总结长度；任一不合法就丢弃本次结果。
- 模型看到的只能是用户确认后生成的低清预览图；默认不开启网络请求，绝不上传原图或本地路径。
- 模型目录按品牌组织，内置火山方舟、MiniMax、OpenAI、Anthropic、Google Gemini、阿里百炼、xAI、Kimi、智谱 GLM、腾讯混元与自定义 OpenAI-compatible 接口。每个目录项声明 API model ID、endpoint、协议 profile、图片输入和 JSON mode 能力；只有图片能力与适配器均已确认的模型可见。完整矩阵见 [品牌与模型目录](../ai/MODEL_CATALOG.md)。
- 模型和 AI 预览尺寸是非敏感全局偏好；每次确认时把 model ID 与尺寸档位写入内存任务上下文，运行中更改设置不会改变已确认批次。两项设置均不进入照片项目状态。
- AI评分关闭深度思考，并忽略 Responses API 中非文本的思考项；只有 `output_text` 中通过本地严格契约校验的 JSON 才能进入全局排序。
- 每次只允许一批 2–5 张缩略图，请求之间保持自适应间隔（基线 4 秒，被限流后收紧，上限 60 秒）。超过 5 张时，App 不会拆分并悄悄上传。
- 每个供应商 API Key 仅保存到当前 Mac 的独立 Keychain 条目；不会写入 UserDefaults、项目文件、日志、导出目录或测试数据。方舟沿用既有 Keychain service 名，升级后无需迁移明文 Key。自定义 endpoint、显示名和 model ID 为非敏感设置，可写入 UserDefaults。
- 新 API Key 只有在用户主动点击验证后，使用 1 张 App Bundle 内置测试图走完正式图片请求、协议适配器与 Validator 并成功，才写入 Keychain。验证失败不保存新 Key；内置测试图不来自用户照片。
- 已验证的具体 model ID 作为非敏感偏好写入 UserDefaults；同品牌切换到未验证模型时不能开始评分。替换或删除品牌 Key 会清除该品牌所有 model ID 的验证状态。
- OpenAI / Anthropic 账号模型刷新只调用品牌模型列表接口，不发送图片；列表结果不落盘。用户选中的额外 API model ID 和显示名作为非敏感配置持久化，协议和 endpoint 继续由品牌固定。
- 供应商返回的工具参数或文本先解析为只含 `reviews` 的 JSON，再由 App 补回本地请求 ID 和评分范围，并执行全部契约校验。格式错误、跨范围、缺图、重复照片或越界分数会丢弃本次结果。
- 每条 `review` 必须包含 `dimensions.moment/composition/subject/lighting/storytelling` 五个 0–100 整数，以及 4–120 字的 `summary`。App 不根据维度重新计算 `score`；不同模型的权重由各模型在 Prompt 约束下自行决定。
- 对于非 2xx 响应，App 只会从 JSON 中提取长度不超过 80 个 ASCII 字符的机器错误码；绝不显示服务端的 `message`、`detail`、`status_msg` 或原始响应正文，避免意外回显请求数据。

## 本地待评分池

`LocalAestheticCandidatePlanner` 先在本地把大照片集压缩成受控候选池：

- 待评分数量按剩余保留目标的 2–3 倍弹性收敛：倾向于为每个名额保留 2 张比较图，只有本地技术信号足够强时才扩展到 3 倍。上限随剩余目标放宽（默认目标下为 48 张，绝对上限 240 张），不得为填满上限加入弱候选或同场景照片。
- 候选数与目标的比例不构成开始条件：候选多于目标时 AI 的挑选空间更大，少于目标时最终只选出候选那么多张，两种情况都必须允许开始。
- 人工 `keep` 已经锁定，无需再参加竞争；人工 `reject` 永远不会进入待评分池。
- `CandidateFamilyIndex` 只根据画面相似集合建立候选家族。严格画面相似不要求时间接近；画面中等相似只有在两分钟内才形成同场景集合。每个家族最多输出一个本地技术代表；家族中已有人工 `keep` 时，其他成员不会进入待评分池。
- 无分组普通照片全部具备参选资格。容量同时存在家族代表与普通照片时，两类至少各有一个席位；普通照片按旅途时间线分段抽样，避免只来自某一小段行程。
- 候选计划记录家族代表数、普通照片可选/入选数、被折叠兄弟照片数和因人工锁定被排除数，供界面解释漏斗。
- 候选池只包含运行时本地 ID；生成它不会读取图片、生成 JPEG、访问 Keychain、改变人工决定或发起网络请求。

## AI评分批处理

`AIFinalSelectionRunPlanner` 分别把人物或风景候选池切成 2–5 张的同类型传输窗口，每张候选只评分一次。窗口只用于供应商请求和限流，不形成局部名次或胜者。当前类型全部候选成功后，App 只在该类型内按总分和五维分执行一次全局稳定排序，取该类型剩余目标数量的前 N 张。

- 运行前的确认弹窗只用一句话说明模型、张数和照片类型；endpoint 与评分图片尺寸常驻侧栏，完整的请求节奏、排序、重试与费用规则放在“帮助与支持”。用户确认后才读取 Keychain 与生成预览。
- 执行器是有限队列，不会自行增加候选或请求。支持暂停下一次请求、继续、停止和失败范围重试。
- 可自动重试的错误：模型输出格式或可恢复字段异常、HTTP 429、HTTP 5xx、连接超时与网络中断；最多自动重试 4 次，按指数退避并优先遵守 `Retry-After`。
- 不可自动重试的错误：鉴权失败、模型权限不足、模型 ID 错误、请求构造非法。
- 确认文案必须披露自动重试会产生额外请求与费用。自动重试仍失败时停止后续发送，已通过契约校验的独立评分与累计 token 统计保留，用户可从中断处继续。
- 失败状态保留下一照片范围与已完成评分，只允许从失败范围继续；安全诊断仅区分响应外层、缺少工具/JSON 载荷、载荷字段错误等阶段，不保存或展示服务端原始内容。
- 所有供应商请求走同一个 ephemeral `URLSession`（`AIReviewURLSession.shared`）：禁用磁盘 URLCache、Cookie 与凭据存储，请求超时 180 秒、资源超时 600 秒。因此 AI 原始响应与供应商会话状态在构造上就不会落盘。
- 每次请求继续使用匿名 `photo_001` 等 ID、已锁定尺寸的无元数据内存 JPEG 和既有严格响应校验。只有当前类型全部候选成功且类型内排序再次通过候选范围与唯一性校验后，才写入运行时该类型的 `aiFinalSelectionPhotoIDs`；最终张数取剩余目标与实际候选数中较小的一个。
- `已AI评分` 展示所有至少有一条有效评分记录的照片，`评分优先` 只展示整轮最终胜出集合；两者都不会自动把照片标记为 `keep` 或 `reject`。人工保留项作为锁定结果计入最终 N 张，人工决定始终优先。
- AI 胜者与人工锁定照片合并后，必须再通过 `CandidateFamilyIndex` 冲突审计；同一家族出现两张及以上时，结果整体不生效。人工已保留冲突会在运行前提示用户处理。

## PhotoProject（持久化项目）

- `id`：跨 App 重启保持稳定的 UUID。
- `folderURL`：只在本机运行内存中使用的标准化目录 URL，不进入导出、日志或版本库。
- `displayName`：由上级目录和当前目录组合，例如 `20260802美国 / 2`。
- `photoCount`、`isAnalysisComplete`：用于项目列表展示。
- 切换项目时保存内存快照；删除项目时移除快照、照片数组和撤销历史，并清空缩略图缓存。
- 跨 App 重启仅保存只读 security-scoped bookmark、最小项目元数据、人物/风景目标数量、当前选中照片的相对路径、非待定人工决定和用户纠正的类型；自动分类与评分结果仍在恢复后重新计算。
- 书签失效或目录不可读时保留项目记录并要求用户通过系统文件夹选择器重新授权。

## DemoModeSession（不持久化）

- 固定读取 App Bundle `DemoPhotos` 中列明的 4 张人物和 4 张风景 JPEG；不枚举用户目录。
- 人物和风景分别构造 `finalSelection` 传输窗口和固定独立评分，每个响应仍通过版本、请求 ID、带类型 scope、匿名 ID、总分、五维评分、具体评价和总结校验。
- 两类照片完成后分别按同一稳定排序器选出人物 2 张、风景 2 张，结果通过候选范围、唯一性和各类精确数量校验后才写入对应运行时结果。
- `PhotoLibraryViewModel` 在演示启动时不调用任何供应商 Key 状态探针；演示代码不引用 `URLSession`、供应商 KeyStore 或模型 API URL。
- 演示项目没有 `PersistedPhotoProject`，不会进入项目 catalog；进入演示前的真实 active project ID 继续作为 catalog active ID。
- 退出或切换到真实项目时移除演示项目与内存快照。人工决定和导出仍走正式路径。

## CategorizedExportManifest

一次导出创建一个时间戳根目录，并在其中创建本地化的“人物”和“风景”子目录。根目录 `selection.json` 和 `selection.csv` 只记录导出时间、类别、数量和相对文件名；不写入源文件绝对路径，也不写入任何 API Key。

- 导出目录不得等于项目目录或位于其内部；选择时即拒绝，不进入确认弹窗。
- `selection.csv` 以 UTF-8 BOM 开头：类别目录名是中文，没有 BOM 时表格软件会显示乱码。
- 根目录使用 `withIntermediateDirectories: false` 创建，因此永远不会写入或合并已存在的目录；
  中途失败时只删除本次刚创建的导出目录。

## SelectionTarget

- `peopleTargetCount`、`sceneryTargetCount`：用户分别设定的人物与风景精选数量，范围均为 0–999，默认分别为 6。
- 旧项目只有总目标 N 时按 `ceil(N / 2)` 与 `floor(N / 2)` 拆分，保证迁移前后总目标一致。
- 目标只用于显示进度和收敛待评分池，不是导出闸门：只要有至少一张保留照片就可以导出，与目标的差异只在确认弹窗中提示。导出服务只拒绝空选择和仍未完成分类的照片。

## PrivacyInfo.xcprivacy

- `NSPrivacyTracking`：`false`；App 不包含广告或分析 SDK，不进行跨 App 或网站跟踪。
- `Photos or Videos`：只对应用户确认后发送给所选供应商的 512–1536px 去元数据预览；用途为 App Functionality，不用于跟踪。由于同一请求携带用户自己的供应商 API Key，按可关联到供应商账号的数据保守声明。
- `User ID`：对应作为 HTTPS Authorization 请求头发送给所选供应商的用户自有 API Key；用途为 App Functionality，不用于跟踪。
- `File Timestamp / 3B52.1`：App 只读取用户通过系统文件夹选择器明确授权目录内的文件创建/修改时间，用于缺少 EXIF 时的本地时间线排序，并辅助判断画面中等相似照片是否来自同一场景；时间不能单独形成相似照片集合。
- App 内“隐私与数据”、公开隐私政策和 App Store Connect 答案必须与该清单同步更新。
