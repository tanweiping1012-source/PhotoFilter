# AI 独立评分与全局排序规格

## 问题

一次网络请求中的 2–5 张照片只是传输、限流和费用控制窗口，不是用户概念中的候选组。旧 Prompt 要求模型比较这些照片并返回唯一名次，执行器再让每个请求范围的第一名晋级。这样会产生两个错误：

- 评价中出现“本组更好”“相比同组”等没有稳定含义的相对表述；
- 同一批候选采用不同请求切分时，最终结果可能改变。

## 新评分契约

- 模型对每张照片独立使用同一套 0–100 标尺评分。
- 人物和风景共享分数范围，但使用不同观察重点，并且每次请求只包含同一类型。
- Prompt 明确禁止比较附带照片，禁止返回名次，禁止使用“本组、相比、更好、更差、优先、候补”等相对措辞。
- 本地 Validator 再次拦截上述相对措辞；不合规结果不会展示，并按可恢复格式错误重试。
- 每张照片仍返回总分、五维分、1–3 条具体评价和总结。
- 2–5 张照片可以同一次传输，但每张评分必须只依据自身画面。
- App 校验匿名照片集合、分数范围和文本字段，不再校验请求内名次。

统一标尺：

- 90–100：少见且完成度很高；
- 80–89：明显优秀，主体、瞬间或叙事有突出表现；
- 70–79：整体可用，但仍有明确不足；
- 60–69：存在明显画面或表达问题；
- 0–59：严重技术问题或缺少有效主体与表达。

## 全局排序

当前人物或风景 AI评分成功后，App 汇总该类型本轮所有候选的独立评分，再执行一次类型内全局排序：

1. 总分降序；
2. 五维分总和降序；
3. 叙事、瞬间、构图、主体、光线依次降序；
4. 本地照片 ID 仅作为完全同分时的稳定顺序。

该类型前 N 张与同类型人工已保留照片合并，形成该类型的“评分优先”。人物和风景不互相比较，也不生成跨类型总名次。任何请求失败时都不生成该类型的不完整最终结果。

## 请求边界

- 请求窗口仍为 2–5 张，至少间隔 60 秒。
- 规划器按最多 5 张切分并避免单张尾项，不再让请求数量等于保留目标。
- 同一轮始终锁定模型、接口和图片尺寸。
- 同一轮同时锁定人物或风景类型，运行中不能混入另一类型照片。
- 固定标尺可以降低跨请求漂移，但不能保证不同模型或多次运行的绝对分数完全一致。
