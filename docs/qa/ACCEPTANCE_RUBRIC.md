给独立测试者（人或 Agent）的一份可执行验收清单。目标不是复述功能列表，而是

## 0. 这个 App 的承诺是什么

判断"是不是 bug"之前，先知道它承诺了什么。以下五条是产品主张，
**任何一条被违反，严重度自动 ≥ 严重**：

| # | 承诺 | 含义 |
|---|---|---|
| P1 | **原图绝不被改动** | 只读取、只复制。任何移动、删除、改写、写入 EXIF 都是事故 |
| P2 | **本地优先** | 只有 AI 评分这一步联网。扫描、分析、分类、相似分组、导出全部离线 |
| P3 | **决定始终在用户手里** | AI 只产出分数和排序。没有用户的"采纳"，任何照片的保留/淘汰状态都不该改变 |
| P4 | **花钱必须知情** | 每次可能产生 API 费用的动作，之前都要有明确确认；进行中要能看到进度、能暂停、能停止 |
| P5 | **不上传原图与身份信息** | 只发送内存中生成的匿名 JPEG 预览。不发原文件、文件名、本地路径、EXIF/GPS |

## 1. 环境与安装

### 1.1 前提

- macOS 14.0 或更高
- Apple Silicon 或 Intel（DMG 是 universal）
- 磁盘可用空间 ≥ 1 GB
- **测试用照片**：建议准备 2 组
  - 小组：20–50 张 JPEG/HEIC，其中包含 3–5 组连拍或近似重复、2–3 张明显过曝或欠曝、若干张有人物
  - 大组：500 张以上，用于压力与性能观察

### 1.2 下载

```
https://github.com/tanweiping1012-source/PhotoFilter/releases/tag/v0.8.1
```

文件：`TravelPhotoFilter-0.8.1-macOS-universal.dmg`
SHA-256：`d600424349961e7811fa5952bd70769b91d0b78ed0c0338060ef49b6b5ae8e0c`

下载后先校验：

```bash
shasum -a 256 ~/Downloads/TravelPhotoFilter-0.8.1-macOS-universal.dmg
```

**校验不通过就停止测试并报告。**

### 1.3 安装（App 未签名，这是已知情况）

1. 双击 DMG，把「旅行照片筛选器」拖进「应用程序」
2. 首次打开会被 Gatekeeper 拦下
3. 打开**系统设置 → 隐私与安全性**，在底部找到被拦截的提示，点**仍要打开**

> 这一段本身也是验收项：**如果按上述步骤仍然打不开，是阻断级问题。**

### 1.4 重置到"全新安装"状态

多次测试首次体验时需要：

```bash
# 退出 App 后执行
defaults delete com.photocurator.local 2>/dev/null
rm -rf ~/Library/Containers/com.photocurator.local
```

> API Key 存在 Keychain（每个供应商独立 service），上面两条不会删它。
> 需要清除时在**钥匙串访问**里搜索 `photocurator` 手动删除。

## 2. 严重度定义

| 级别 | 判据 |
|---|---|
| **阻断** | 无法安装或启动；数据丢失；原图被改动/删除；崩溃且无法恢复 |
| **严重** | 违反第 0 节任一承诺；核心流程走不通；花了钱但拿不到结果；结果错误且用户无从察觉 |
| **一般** | 流程能走通但明显别扭：文案与实际不符、状态显示错误、性能明显不可接受、错误没有解释 |
| **建议** | 不影响正确性的改进：措辞、布局、可发现性 |

**报告时优先写"你观察到什么"，而不是"你猜是什么原因"。** 猜测放在单独一行。

### A. 首次启动 🟢

| # | 操作 | 期望 |
|---|---|---|
| A1 | 全新安装后首次打开 | 出现「第一次筛选」引导页，提供"用示例练习"和"选择我的照片文件夹"两条路 |

| A4 | 查看侧栏「隐私与数据」 | 说明与实际行为一致：只发匿名 JPEG 预览、不发原图/文件名/路径/EXIF |
| A5 | 首次启动不询问任何账号、登录、订阅 | 无账号体系 |

### B. 新手引导全流程 🟢

**这是不花钱就能覆盖的最大一块，请完整走完。** 内置 8 张示例照片，全程离线。

| # | 操作 | 期望 |
|---|---|---|
| B1 | 进入示例练习 | 出现 8 张照片，开始本地分析，有进度 |
| B2 | 逐步跟随任务条走完 8 步（任务条显示 N / 8）| 每一步的红框都指向**真实存在且可点**的控件 |
| B3 | 对照每一步的说明文字与实际发生的事 | **文案必须与实际操作一致**。任何"叫你点 X，但实际要点 Y"都是严重 |
| B4 | 观察评分进行中的进度数字 | 分子**永远不得超过**分母；进度条不得在未完成时跑满 |
| B5 | 中途关闭大图、切换照片类型、点侧栏别处 | 引导不应卡死或跳步；能回到正确的下一步 |
| B6 | 走到"采纳"之前，检查照片状态 | **采纳前，没有任何照片因为评分而变成"保留"**（P3） |
| B7 | 完成导出 | 得到「人物」「风景」两个子目录，共 4 张 |
| B8 | 结束引导后 | 示例项目消失，回到干净状态，不残留示例照片 |

> **重点观察**：这一版重写了全部 8 步的说明文字，目标是每步都回答"做什么"
> **和**"这一步意味着什么"。请判断：只看任务条，你能不能理解"评分"和"保留"
> 是两件不同的事？如果不能，指出是哪一步没讲清。

### C. 真实照片的本地分析 🟢

| # | 操作 | 期望 |
|---|---|---|
| C1 | 选择小组照片文件夹 | 立刻显示照片，分析在后台推进，期间可以手动选片 |
| C2 | 观察分析进度 | 数字单调递增，不超过总数，完成后状态变为"分析完成" |
| C3 | 检查相似照片分组 | 连拍/近似重复被分到同一组，标为「相似 1/N」。**不同场景不该被分到一组** |
| C4 | 检查人物/风景分类 | 主体是人的归人物；背景里有路人的街景应归风景 |
| C5 | 检查技术风险标注 | 明显过曝/欠曝/模糊的照片被标出；正常照片不该被误标 |
| C6 | 手动纠正一张照片的类型 | 立即生效；照片从当前类型视图消失或徽章改变 |
| C7 | 分析进行中切换项目/新建项目 | 应被阻止并给出可理解的原因，或安全地取消当前分析 |
| C8 | 大组（500+）照片 | 观察：是否卡死、内存增长、风扇、总耗时。**卡死不恢复是阻断** |
| C9 | 分析进行中强制退出 App，重新打开 | 项目仍在，不需要重新授权（或明确提示重新授权），无数据损坏 |

### D. AI 评分 🔴

> **执行前必须得到委托人明确批准**，因为会消耗真实 API 额度。
> 建议先用 5–10 张的小文件夹做一次，确认链路通了再考虑更大规模。

| # | 操作 | 期望 |
|---|---|---|
| D1 | 未配置 Key 时点"开始 AI评分" | 按钮应置灰，**下方给出可理解的原因**，而不是点了没反应 |
| D2 | 在「AI评分设置」中配置并验证 Key | 有明确的验证结果；失败时说明原因 |
| D3 | 点"开始 AI评分" | **必须出现确认框**，说清将发送多少张、发给谁、什么尺寸（P4/P5） |
| D4 | 确认后观察侧栏 | 进度条 + "已评估 N/M 张" + 进度条正下方有一行说明当前在做什么 |
| D5 | 点"暂停"再"继续" | 状态正确切换，不重复计费已完成的照片 |
| D6 | 点"停止" | 已完成的评分保留，但不产生最终结果 |
| D7 | 评分中拔掉网络 | 自动退避重试；重试次数用尽后停在当前进度，**可以从中断处继续**，不从头重跑 |
| D8 | 完成后查看单张评分 | 五个维度分 + 1–3 条具体评价 + 总结 |
| D9 | 阅读评价文字 | **不得出现"本组""相比""更好""优先""候补"等相对表述**（每张是独立评分） |
| D10 | 完成后不点"采纳" | 照片状态不变（P3）。"采纳"才把建议变成"保留" |
| D11 | **退出 App 再打开** | 观察 AI 评分结果是否还在 —— 见第 4 节已知问题 |

### E. 评分权重（本版新增）🟢

> 前置：需要有已评分的照片。可以用**新手引导的示例**满足，不必花钱。

| # | 操作 | 期望 |
|---|---|---|
| E1 | **在不被提示的情况下，尝试找到调整评分权重的入口** | 记录你花了多久、走了哪些弯路。**找不到或找错地方本身就是发现** |
| E2 | 展开「评分权重」，拖动任意一维 | 全部照片的总分和排序**立即更新**；**不应发生任何网络请求，不产生费用** |
| E3 | 把某一维拖到 0 | 该维度在评分详情里变暗并标明未计入总分 |
| E4 | 把五维全部拖到 0 | 给出提示并退回等权，**不应出现 0 分或崩溃** |
| E5 | 调完权重后退出 App 再打开 | 权重设置保留 |
| E6 | 同一张照片，等权 vs 偏重某一维 | 总分应当变化，且变化方向符合直觉 |
| E7 | 判断这个功能是否讲清楚了 | 用户能否理解"改权重不重新评分、不花钱"？如果不能，指出缺在哪 |

### F. 导出与原图安全 🟢

> **这一组直接验证承诺 P1，请务必做。**

| # | 操作 | 期望 |
|---|---|---|
| F1 | 导出前，对源文件夹做全量校验和 | `find <源目录> -type f -exec shasum -a 256 {} \; \| sort > /tmp/before.txt` |
| F2 | 执行导出 | 出现确认框，说清会复制多少张、放到哪里 |
| F3 | 导出后，再次计算源文件夹校验和并比对 | `diff /tmp/before.txt /tmp/after.txt` **必须完全一致**。任何差异都是阻断 |
| F4 | 检查导出结果 | 「人物」「风景」两个子目录；张数与界面显示一致 |
| F5 | 比对导出文件与原文件 | 应为逐字节一致的副本（原图未被重新编码） |
| F6 | 尝试把导出目录选在源照片文件夹**内部** | 应被拒绝并说明原因 |
| F7 | 一张都没保留时点导出 | 按钮置灰或给出可理解的提示 |

## 4. 已知问题（**不要重复报告**）

### 4.0 v0.8.1 修掉了什么（请重点复验）

**停止后重新开始不再重发已评分照片。** v0.8.0 里，18 张候选跑到 `1/18` 时点"停止"，
再点开始会把已经评过、已经付过费的第一张重新发送一遍。现在：

- 按钮改说"继续人物 AI评分（还剩 17 张）"，发送确认框也只说 17 张，并注明
  已评分的那张不会重新发送、不会再次计费。
- 进度从 `1/18` 接着走，不回到 `0/17`；token 用量接着累加。
- 整轮结束时仍对**全部 18 张**排名次——停止前和继续之后的分数合并后一起排。
- 换过模型或预览尺寸的旧分数不复用，整池重评（两套标准的分数不能排进同一个名次）。
- 候选全部评完后开始按钮置灰，不会再拿同一批照片花第二次钱。

请复验：停止 → 继续，第一张是否只被发送过一次；最终名次是否覆盖全部候选。

1. **App 未使用 Developer ID 签名、未做公证**，首次打开需要手动放行。
