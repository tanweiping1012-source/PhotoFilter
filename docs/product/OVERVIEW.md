# 产品说明

旅行照片筛选器是一个本地优先的 macOS App。它把一个日期文件夹变成一个筛选项目，
在本机完成人物/风景分类、相似照片识别与技术分析，带用户逐张做保留或淘汰的决定，
最后把选中的照片**复制**到新目录。原图全程只读。

本文是产品行为的权威定义：界面文案、门禁脚本与验收记录都以这里为准。
细节各有专文，本文只做汇总并给出链接，不重复展开。
实现落在哪些文件见[代码结构](../engineering/ARCHITECTURE.md)，
字段级定义见[数据契约](../engineering/DATA_CONTRACTS.md)。

## 不变量

1. **原图只读。** 没有删除、移动、改名、写回；导出只有复制一条路径，并需要用户确认。
2. **人工决定优先。** 相似关系、技术风险和 AI 评分只生成候选与顺序，永远不改变 keep/reject。
3. **发送边界。** AI 只收到用户确认后生成的匿名低清预览，不含原图、文件名、路径或 EXIF/GPS。
4. **执行入口固定。** 已实现的能力必须有可发现且位置稳定的入口；不满足前置条件时置灰并在旁边
   说明原因，绝不整个隐藏——入口消失会让用户以为功能不存在或界面出错。
5. **完成态可见。** 主链路上的每一步完成后都要有明确回执，并指出下一步在哪，
   而不是只在状态栏留一行灰字。

## 扫描与分析

选择文件夹后 App 先显示可浏览的照片网格（约 0.1 秒），EXIF、相似关系、技术风险和人物/风景分类
在后台逐步完成。用户可以在分析过程中就开始手动选片，后到的分析结果不会覆盖人工决定。

递归扫描 JPG / JPEG / PNG / WebP / HEIC / HEIF / TIFF，跳过隐藏文件与包内容。
目录里没有受支持的照片时，空状态直接说明这一点并列出支持的格式，而不是继续显示"选择照片文件夹"。

本地分析进行中不能新建或切换项目：半分析状态无法安全保存，切走再回来会得到一个
"看起来分析完了、其实没有相似关系"的项目。此时入口置灰，并在按钮下方说明还要等什么。

## 人物与风景

照片在后台通过本机 Apple Vision 自动分为人物和风景。"人物"要求人物承担主要视觉主题：
清晰正/侧脸、大比例人物主体，或在风景中具有明确视觉权重的人物/剪影；
远处路人和背景人群仍归为风景。分类只用于整理，用户可在照片卡或大图中纠正，人工纠正优先并持久化。

主界面用"全部 / 人物 / 风景"三段选择切换照片范围，状态筛选独立工作。
用户分别设置两类的精选数量，默认总数 12 张拆为人物 6 张、风景 6 张。
目标用于显示筛选进度和引导 AI评分的候选规模，**不限制导出**：
只要有至少一张保留照片就可以复制导出，保留数与目标不一致时只在确认弹窗中提示。

判定语义与阈值见[人物主题本地分类](PEOPLE_CLASSIFICATION.md)，
两条赛道的完整规则见[人物与风景分开筛选](CURATION_SCOPES.md)。

## 相似照片与待评分池

画面相似为主、时间只做辅助：严格近重复不要求时间接近，画面中等相似必须同时满足拍摄时间接近。
每个相似家族只输出一个本地技术代表，已有人工保留的家族不再输出其他成员。
分组规则见[相似照片识别策略](SIMILAR_PHOTOS.md)。

本地分析完成后，App 为人物和风景分别生成只存在于内存的待评分池。普通照片全部具备参选资格，
并按旅途时间线分段抽样，避免候选只集中在某一个片段。每类待评分池按该类剩余目标的 2–3 倍弹性收敛，
上限随剩余目标放宽（默认目标下为 48 张，绝对上限 240 张），而不是强制凑满。
人工淘汰项绝不会进入。生成待评分池不读取 Keychain、不重编码图片、不发起网络请求。

**候选数与目标的比例不是开始条件**：候选多于目标只是让 AI 有更大的挑选空间，
候选少于目标时最终只选出候选那么多张，两种情况都允许开始。

## AI评分

AI 对待评分池中的每张照片使用同一绝对标尺独立评分，人物和风景使用不同的观察重点。
每次请求只携带 1 张照片，因此同一请求内不可能出现照片之间的相互影响。
全部候选成功后，App 只在当前类型内按总分和五维分执行全局排序，
取剩余目标与实际候选数中较小的那个数量作为 AI 推荐保留；任一请求失败时不会生成该类型的不完整结果。

评分契约、统一标尺、排序规则、进度表达与查看路径见 [AI评分](../ai/SCORING.md)。

### 一轮任务只锁自己那一类

人物和风景各有独立的目标、候选池、运行状态和结果，因此一轮评分只锁定它自己那一类：

- 正在评分的类型：不能改目标、不能改这些照片的决定或分类、不能撤销涉及它们的操作。
- 另一类：浏览、保留、淘汰、撤销、调整目标全部照常可用。
- "照片类型"三段选择在评分期间始终可切换；运行中的进度、暂停和停止按钮跟着任务走，
  切到另一类浏览时不会消失，并标明正在评分的是哪一类。

### 完成后把用户送到结果

一轮评分成功结束时，App 自动把照片类型切到刚评完的那一类，把状态筛选切到"已AI评分"，
并在网格上方给出完成回执：多少张已评分、AI 推荐保留多少张、下一步该做什么。
用户不需要自己回想该切回哪个类型、该选哪个筛选。采纳仍然只有底部命令条一个入口。

### BYOK 与设置

发行版本采用 BYOK：本地筛选、人工决定与安全导出不依赖云端。需要 AI评分时，用户先选择品牌，
再选择该品牌下支持图片输入的具体模型、评分图片尺寸并提供对应 API Key。
内置覆盖火山方舟、MiniMax、OpenAI、Anthropic、Google Gemini、阿里百炼、xAI、Kimi、
智谱 GLM、腾讯混元与自定义 OpenAI-compatible 接口。新 Key 使用 1 张内置测试图验证鉴权、
模型权限、图片输入和正式评分契约后才保存；验证可能产生少量供应商费用。
App 不销售、代充或跳转购买 API Key，各品牌 Key 使用独立 macOS Keychain 条目。

AI评分设置是侧栏中的全局入口，不要求先创建照片项目；样例练习中隐藏该入口，
以保持练习模式不读取 Keychain。项目侧栏中的 AI评分区只展示当前模型、待评分数量、
运行状态和开始入口，不提供第二个设置入口。

## 界面与操作

左侧是可新建、切换和删除的项目列表。照片网格顶部只放网格级控件，并按中线对齐：
先以"全部 / 人物 / 风景"选择类型，再用唯一状态筛选框选择
"全部照片 / 待AI评分 / 已AI评分 / 保留 / 淘汰 / 待定"，最后是当前显示数量。
不设"评分优先"筛选：AI 推荐结果只存在于内存，重启后对该项目永久为空，
一个大多数时候是空的筛选项只会增加理解成本。最终结果由底部"采纳"命令承担。
显示数量是筛选操作的唯一反馈，字号必须可读、不得被截断。

窗口底部是两条固定条：上面一条是当前选中照片的检查条（缩略图、文件名、相似位置 / 技术风险 /
AI 分摘要、进入大图的按钮），下面一条是命令条（撤销、恢复待定、淘汰、保留、采纳评分结果、导出）。
选中照片的信息与可执行命令放在一起，不与网格级控件混排；决定命令在任何窗口宽度下都保持文字标签，
与大图预览中的同名按钮一致。

所有筛选只改变可见范围，不删除、移动或修改原图。筛选结果为空时，空状态说明原因并提供
"显示全部照片"出口——任何筛选都不允许把用户困在一个没有出路的空网格里。
项目切换时筛选器复位为"全部照片"：它是窗口级状态，跨项目残留会让新项目看起来一张照片都没有。

照片卡用于快速扫描：缩略图保留原始长宽比以便判断构图，卡面最多显示两个信息徽章
（按 AI 总分、技术风险、相似照片位置、待评分状态取前两个），当前筛选已经蕴含的信息不再重复显示，
文件名放在悬停提示中。双击卡片、按空格、点击检查条中的预览按钮或右键"查看评分"可进入只读大图检查。
大图沿当前筛选结果连续切换，并集中展示相似照片位置、技术风险，以及 AI 总分、五维评分、
具体评价和总结；人工决定与底部命令共享同一 ViewModel 状态。

一次导出会在同一时间戳目录中生成"人物"和"风景"两个子目录，并写出 `selection.json` 与 `selection.csv`。
导出完成后网格上方出现回执，说明复制了多少张、放在哪里，并提供在访达中打开结果目录的入口。

## 隐私与数据

侧栏底部提供始终可访问的"隐私与数据"入口，明确本地处理、持久化字段、所选供应商 Authorization、
预览图发送范围、账号关联、无跟踪声明和删除方式。隐私清单对用户确认后发送的预览图和供应商账号标识
按"App 功能、关联用户、不跟踪"保守披露；文件时间戳只用于用户明确授权目录内的本地时间线排序，
并辅助判断画面中等相似照片是否来自同一场景。

## 首次使用与离线教学

首次正常启动展示一次"第一次筛选"场景首页，也可从侧栏随时重开。示例使用 4 张人物和 4 张风景，
在真实照片网格中完成八项任务；8 张样例初始没有评分，只有用户主动运行演示后才按人物和风景分别写入
通过正式契约校验的固定结果，并按已评估照片数量逐步出现。示例不打开文件夹选择器、不读取 Keychain、
不访问用户项目或网络，也不进入项目持久化；人工决定、采纳和复制导出继续使用正式业务路径。
内部 `--review-demo` 自动审核模式直接进入任务，不叠加首次弹窗。

完整任务、聚焦规则与完成出口见[新手引导与第一次筛选教学](ONBOARDING.md)。
