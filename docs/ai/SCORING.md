# AI评分：契约、排序与进度

一次 AI评分的完整定义：模型看到什么、返回什么、App 怎么校验、怎么排序、怎么呈现进度、
完成后把用户带到哪。原来拆成"全局排序 / 评分详情 / 评分进度"三份，同一套规则被抄了三遍。

供应商与协议见[供应商与协议适配](PROVIDERS.md)，图片尺寸见[评分图片尺寸](PREVIEW_SIZE.md)，
机器可读的响应契约见 [REVIEW_SCHEMA.json](REVIEW_SCHEMA.json)。

## 为什么是独立评分而不是组内比较

一次网络请求携带 2–5 张照片，那只是传输、限流和费用控制的窗口，不是用户概念中的"候选组"。
早期 Prompt 要求模型比较这些照片并返回名次，执行器再让每个请求的第一名晋级。这产生两个错误：

- 评价里出现"本组更好""相比同组"这类没有稳定含义的相对表述；
- 同一批候选换一种请求切分，最终结果就会变。

所以：**模型对每张照片独立评分，名次由 App 在本机产生。**

- Prompt 明确禁止比较附带照片、禁止返回名次、禁止使用"本组、相比、更好、更差、优先、候补"等相对措辞。
- 本地 Validator 再次拦截上述相对措辞；不合规结果不展示，并按可恢复格式错误重试。
- 人物和风景共享同一分数范围，但观察重点不同，且每次请求只包含同一类型。

## 统一标尺

锚点：**80 分 = 专业摄影师在同类题材上的交付水准**。

| 区间 | 含义 |
|---|---|
| 90–100 | 极少见的杰作，构图、光线、瞬间与叙事同时达到发表级 |
| 80–89 | 专业摄影师水准，明显优秀且几乎没有可挑剔的硬伤 |
| 70–79 | 高于平均的合格旅行照片，有亮点但存在明确不足 |
| 60–69 | 普通记录性快照，能看出场景但缺少摄影层面的表达 |
| 0–59 | 明显技术问题，或缺少有效主体与表达 |

评分要求严格：绝大多数旅行照片应落在 60–79。不得因为画面讨喜、色彩鲜艳或有纪念意义而抬分；
给出 80 分以上必须能在具体评价中指出达到专业水准的理由。

固定标尺可以降低跨请求漂移，但不保证不同模型或多次运行的绝对分数完全一致。

## 每张照片返回什么

- `score`：0–100 总分，由模型直接返回。
  本地不按维度重新加权——那等于用 App 的权重假设静默覆盖供应商的。
- `dimensions`：五个 0–100 整数——`moment` 瞬间、`composition` 构图、`subject` 主体、
  `lighting` 光线、`storytelling` 叙事表现。
- `reasons`：1–3 条具体评价。
- `summary`：4–120 字的总结。

照片集合、总分、五维范围、具体评价和总结任一不合规，本次结果整体失效。

## 全局排序

当前人物或风景的全部候选成功后，App 汇总本轮所有独立评分，执行一次类型内全局稳定排序：

1. 总分降序；
2. 五维分总和降序；
3. 叙事、瞬间、构图、主体、光线依次降序；
4. 本地照片 ID 仅作为完全同分时的稳定顺序。

取前 N 张（N 为该类型剩余目标与实际候选数中较小的一个），与同类型人工已保留照片合并，
形成该类型的"评分优先"。人物和风景不互相比较，也不生成跨类型总名次。
任一请求失败时都不生成该类型的不完整最终结果。

## 请求边界

- 请求窗口 2–5 张，请求之间保持自适应间隔（基线 4 秒；被限流后按 `Retry-After`
  或指数退避收紧，上限 60 秒）。
- 规划器按最多 5 张切分并避免单张尾项，请求数量与保留目标无关。
- 同一轮锁定模型、接口、图片尺寸和照片类型，运行中不能混入另一类型照片。

## 进度怎么表达

用户只需要知道：一共要评估多少张、已经完成多少张、当前在评估第几张到第几张、失败后从哪几张继续。
**界面不展示"批次""第 N 批"或总批次数。**

- 主状态：`正在评估 · 已完成 12 / 15 张`
- 当前请求：`正在评估第 13–15 张，共 15 张`
- 失败恢复：`重试第 13–15 张`
- 开始操作：`开始人物 AI评分（15 张）`；不可开始时按钮置灰并在下方说明原因，入口位置不变
- 离线教学：`离线演示 4 / 8 张`

进度条使用 `completedPhotoCount / candidatePhotoCount`。内部仍按 2–5 张组织请求，
但只有一组结果通过完整校验后，才把该组照片数计入已完成；自动重试不重复增加进度。

## 完成后的落点

整轮成功后 App 自动把照片类型切到刚评完的那一类、把状态筛选切到"已AI评分"，
并在网格上方给出完成回执：已评分张数、进入评分优先的张数、下一步做什么。
回执只陈述结果和去处，不重复底部命令条里已有的"采纳"。

## 查看路径

### 照片筛选

- `待AI评分`：本地候选池。
- `已AI评分`：所有至少有一条合规评分记录的照片，按分数排序。
- `评分优先`：整轮最终胜出集合。

三者都不会自动把照片标记为保留或淘汰。

### 照片网格

已评分卡片显示总分（例如"AI 91分"）。卡片不展示五维详情，保持网格可扫描。

### 选中照片检查条

位于底部命令条上方，显示缩略图、文件名与摘要。选中已评分照片时按钮显示为"查看评分"，
否则显示为"预览"；该命令打开现有大图，不创建第二套浏览页面。

### 大图评分详情

右侧依次展示：

1. 总分；完整一轮结束后同时显示人物或风景分类名次；
2. 五个维度的评分条和数值——条长按 0–100 **绝对刻度**绘制，与右侧数字表示同一件事。
   不使用组内相对映射：同一根条在不同照片之间必须代表同一个分数，
   否则"看条长比较照片"会得出相反结论；
3. 具体评价；
4. AI 总结。

左右键按打开时的筛选结果连续切换，因此可以从"已AI评分"进入后逐张审阅。

## 唯一评分来源

AI评分只有一个入口：侧栏中按类型的完整候选池评分。一张照片的评分记录只会来自整轮 AI评分，
不存在需要分段显示或互相覆盖的多来源评分。

## 兼容与隐私

- 新请求要求完整五维和总结；旧版本运行时结果不持久化，因此无需项目迁移。
- 内置样例提供固定五维与总结，用于离线教学和视觉验收。
- 评分详情只保存在内存，不新增磁盘数据。
- 不展示供应商原始响应，只展示通过契约校验的字段。
