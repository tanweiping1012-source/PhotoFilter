# AI 预览尺寸规格

## 目标

让用户在发送前明确知道 AI 收到的图片细节档位，并可在识别细节、上传量、响应时间和供应商费用之间做选择。

该设置只影响发送给 AI 的内存 JPEG，不影响照片网格缩略图、大图预览、原图或导出副本。

## 三档定义

| 档位 | JPEG 最长边 | MiniMax detail | 适用场景 |
| --- | ---: | --- | --- |
| 小 | 512px | `low` | 默认；主体与整体构图，上传最少、通常费用最低 |
| 中 | 1024px | `default` | 平衡；多人照片、一般清晰度和中等细节 |
| 大 | 1536px | `high` | 远景、小主体、表情和纹理；上传、等待及潜在图像 token 最高 |

默认保持“小”，以兼容 0.3.0 的隐私和费用行为。选择中或大不会发送原文件，只会从原图像素重新编码一个更大的无元数据 JPEG。

不提供 2048px：每批最多 5 张，JPEG 还要编码为 Base64；1536px 已能显著提高细节，同时控制内存峰值、64MB 请求体风险和弱网络失败概率。

## 供应商映射

### 火山方舟

- 发送按照档位重编码的 base64 JPEG。
- 不改变匿名 ID、Responses API 工具调用或严格结果校验。

### MiniMax-M3

- 发送相同的 base64 JPEG。
- `image_url.detail` 映射为 `low/default/high`。
- `image_url.max_long_side_pixel` 显式设置为 512/1024/1536，与本地 JPEG 边界一致。
- MiniMax 官方文档说明图像 token 随图像尺寸和 `detail` 增长；设置页不承诺固定费用，实际以响应 usage 和供应商账单为准。

## 状态与生命周期

- UserDefaults 只保存稳定档位 ID：`small/medium/large`。
- 旧版本没有该键时回退到 `small`，升级后行为不变。
- 档位是全局偏好，不进入照片项目 JSON。
- 单组复核准备确认时复制档位。
- 整轮精选准备确认时复制档位，并在所有批次及自动重试中保持一致。
- AI 任务运行时禁止修改模型和预览尺寸。
- Demo 不读取该 UserDefaults 值来改变固定离线结果，也不生成上传 JPEG。

## 隐私与提示

设置页必须显示：

- 当前档位与精确最长边；
- 小/中/大各自用途；
- 更大图片可能提高细节识别，也会增加上传量、等待时间和供应商费用；
- 始终去除 EXIF/GPS、文件名和路径，始终不发送原图。

每次发送确认和运行状态必须显示已锁定的档位及像素，防止用户误以为设置页中稍后的变化会影响当前任务。
